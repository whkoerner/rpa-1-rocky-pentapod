# Contributing

RPA-1 is currently a single-student project with mentor review.

## Workflow

1. Open an issue describing the requirement, experiment, defect, or safety concern.
2. For design choices, add or update a decision record with alternatives, evidence, and a review trigger.
3. Work on a short branch such as `feat/communicator-phrase-player` or `exp/tendon-hysteresis`.
4. Include a test or measurement with every functional change.
5. Open a pull request even when working alone; use it as a design and safety checklist.
6. Do not merge hazardous hardware changes without an independent mentor or makerspace review.

## Commit rules

- Prefer small commits with one clear purpose.
- Include hardware revision and test ID when a commit changes measured behavior.
- Never rewrite raw test data after publication; add a corrected dataset and explanation.
- Never commit credentials, personal audio, private memories, third-party film assets, or unlicensed designs.

## Definition of done

A feature is done only when its requirement, implementation, version, test method, result, limitations, and safety impact are documented.
