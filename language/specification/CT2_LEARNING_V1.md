# CT2 desktop learning representation, version 1

CT2 adds a **small exact lexical overlay**, not a full natural language or acoustic decoder. The runtime identifier is `CT2`, represented by immutable `Phrase(units, version)` and `Unit(kind, value, case)` records in `software/csp/learning.py`. It is local Python data, not a new Arduino/wire/file transport. CT1 remains independently encoded/decoded by `software/csp/conversation.py`; choose `text_encoding: "ct1"` to generate it again.

## Lossless rules

1. Validate the complete input with the existing 384-byte text bound and control-character rejection. No trimming, Unicode normalization, paraphrasing, truncation, punctuation deletion or whitespace folding occurs.
2. Scan left to right. Prefer the longest supported phrase at a position (`thank you` precedes single words). Match complete words: Unicode word characters, underscores and straight/curly apostrophes block a boundary. `no` does not match inside `nobody`, `no_way`, or `no's`.
3. Supported lowercase, initial-uppercase and ALL-UPPERCASE forms use the same CSP token and an explicit case flag. Initial-uppercase capitalizes only the first letter of the whole entry: `Thank you` qualifies, `Thank You` falls back. Mixed case such as `hELLo` falls back. Matching is ASCII for these dictionary spellings; Unicode text is preserved literally.
4. A token unit stores its registered token ID and case flag, **not a copy of source English**. The decoder looks up the fixed English meaning, then applies that case flag.
5. Everything else, including punctuation, every space, Unicode, unsupported words and unsupported case forms, is an explicit `utf8` unit of ordered four-digit base-five byte symbols. Digit weights are 125, 25, 5, 1. Reject digits outside 0–4, byte values above 255, invalid UTF-8, unknown tokens/case/version and invalid total text. There is no sentence hash or LLM-selected frequency.
6. Decoding reconstructs exact source text. The application compares decoded text to source English before presenting it as translation; audio validates the same equality before accepting rendering. CT2 is trusted local typed data; it is not claimed to have CT1's packet CRC or an acoustic error-correction channel. A future serialized/acoustic transport needs its own framing, integrity and corruption tests.

## Musical rendering

Released CSP YAML owns all lexical pitch/code assignments. They are unchanged. The five-note **core** for a token is identical in every sentence and case form; melody is not generated by a model. Exact legacy `Hello.`, `Yes.`, `No.`, `Help.`, `Thank you.`, and `Goodbye.` retain the complete original CSP rendering, including its header.

For other CT2 text, emit the existing D3/A3 simultaneous phrase header (300ms + 150ms gap at 1×), then a CT2 marker B3/E5 (100ms + 100ms). Every token has a separate 50ms case marker D3 (lower), D4 (initial) or D5 (upper), then a 50ms gap, then the unchanged five-note core at 140ms/note + 35ms gaps, then 100ms token-boundary silence. Case/header markers are framing, not reassigned CSP lexical tokens.

A fallback span starts with B3/E5 for 50ms + 50ms gap. Each byte uses the same four ordered CT1 pitch voices in octaves 3/4/5/6, 65ms/chord. Its following gap is 15ms normally; a literal space uses 100ms, comma/semicolon/colon 150ms, period/exclamation/question mark 300ms. A fallback span ends with another 100ms boundary pause. Punctuation **also retains its literal byte chord**, so different marks are not silently treated as the same text. Non-ASCII punctuation uses ordinary UTF-8 byte chords and the fallback boundary, without semantic guessing. One header begins the reply; terminal punctuation adds the defined sentence pause, not another header. Internal spaces in `thank you` belong to its registered phrase; two spaces cause literal fallback.

`duration_multiplier` multiplies every note duration and silence, including headers/markers. Pitch and volume do not change. No random prosody is applied. PCM rounding can differ by one sample at event boundaries; the displayed estimate sums the actual rounded sample counts. The envelope keeps its click-reducing attack/release shape.

A person may learn the core patterns, but we have **not** tested recognition from a microphone or written an acoustic decoder. `/translate` decodes the typed representation, not a WAV, speaker recording or microphone input. Stop-like words have no hardware authority.

## Honest duration examples

Computed from event/sample counts at 22,050Hz, not measured human listening or inference latency:

| Exact text | 1× | 3× |
|---|---:|---:|
| `Hello.` (legacy CSP) | 1.325s | 3.975s |
| `hello robot` (CT2) | 3.165s | 9.495s |
| `Hello, builder!` (mixed CT2/fallback) | 3.230s | 9.690s |
| 384 unsupported ASCII `x` characters | 31.570s | 94.710s |

The 3× fallback is often impractical for fluent conversation. These changes make short learning exercises repeatable; they do not solve conversational bandwidth. Keep full English visible, mute long audio, or use individual dictionary replay. Volume reduction does not shorten playback.
