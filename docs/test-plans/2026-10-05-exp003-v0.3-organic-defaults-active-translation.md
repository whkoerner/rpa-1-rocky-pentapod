## EXP-003 v0.3 acoustic change

Rocky now consumes Chordic `EXP-003-runtime-v3` from commit:

`1f564424609983147bcf9fa4ef40c4b28a4c35a1`

The semantic codebook remains unchanged from v0.2. The preferred renderer becomes `vocal-v1`.

`vocal-v1` adds:
- phase-continuous F0 integration through each glide;
- the existing low 120 Hz semantic reference register;
- restrained upper harmonics;
- soft glottal-like shaping;
- subtle subharmonic body;
- deterministic low-amplitude aspiration;
- phrase drift and microprosody small enough to preserve the same recognition contour targets.

`contour-v1` remains available as a comparison/reference renderer.

The new renderer is intended to reduce sterile oscillator/chirp character without changing semantics.

## Active translation scheduling

The previous v0.2 strict policy was:

`Chordic finishes -> English begins`

That met source-order logic but did not feel like active translation.

v0.3 now measures the selected local Windows TTS voice before playback by rendering the same SSML to a temporary WAV. The scheduler then calculates:

`start delay = max(0.75 s, Chordic duration - measured English audio duration + 0.75 s)`

The goal is:
- Chordic begins first;
- English begins while Chordic is still sounding whenever the durations allow it;
- the planned English finish remains at least ~0.75 s after Chordic;
- no fixed 0.75-second start is assumed when it would make English finish too early.

If Chordic playback begins while TTS duration measurement is completing, Rocky subtracts elapsed Chordic playback time from the remaining voice delay instead of restarting the whole delay from zero.

This is local/offline System.Speech duration measurement; it does not call a cloud service.

## New preferred defaults

Packaged defaults are now:

- provider: local
- model: qwen3:8b
- language: EXP-003
- tone: vocal-v1
- duration multiplier: 2
- persistent spoken translation: ON on normal Windows playback
- volume: existing 0.12
- CT2/EXP-002 remain selectable compatibility/debug profiles

A WAV-only diagnostic backend does not auto-enable spoken translation.

### Existing user-settings migration

Rocky's setup historically preserved existing `%USERPROFILE%\.rpa1\settings\rocky.json`, which meant old generated defaults could silently override improved packaged defaults forever.

v0.3 adds a narrow migration rule:

If an old settings file has no defaults-profile version **and** still exactly contains the old generated triple:
- `duration_multiplier = 3`
- `text_encoding = exp002`
- `tone_style = resonant`

those three values are treated as stale generated defaults and replaced in memory by the new preferred defaults.

If any of those three fields was genuinely changed, the file is preserved rather than overwritten.
